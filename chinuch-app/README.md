# ארכיון עיצובי Canva — בית חינוך חב"ד

מקום אחד ומוגן לכל העיצובים של בית החינוך: קישורי Canva וקבצים, מסודרים בקטגוריות
של חודשי השנה ושל אירועים מיוחדים, עם רצועת "רלוונטי עכשיו" שמחושבת לפי הלוח העברי.
**הכניסה עם חשבון גוגל**, ורק למורות שמנהלת בית הספר שלהן אישרה.

## הפעלה (חד-פעמי)

1. **פרויקט Vercel** — מייבאים את הריפו (Framework Preset: *Other*).
2. **אחסון נתונים** — Storage → Create → **Upstash Redis**, ומחברים לפרויקט.
   `KV_REST_API_URL` ו-`KV_REST_API_TOKEN` מוזרקים אוטומטית.
3. **אחסון קבצים** — Storage → Create → **Blob** (`BLOB_READ_WRITE_TOKEN`).
   עד שזה קיים, קישורי Canva עובדים והעלאת קבצים מציגה הודעה מתאימה.
4. **כניסה עם גוגל** — ב-[Google Cloud Console](https://console.cloud.google.com/):
   - APIs & Services → **OAuth consent screen**: שם האפליקציה ומייל תמיכה.
   - Credentials → Create credentials → **OAuth client ID** → *Web application*.
   - **Authorized JavaScript origins**: כתובת האתר (למשל `https://designs.example.org`),
     ואם רוצים לבדוק גם בפריוויו — גם כתובת ה-`.vercel.app`.
   - מעתיקים את ה-**Client ID**. (Client secret לא נדרש כאן: אנחנו מאמתים
     ID token בצד השרת ולא מבצעים חילופי קוד.)
5. **משתני סביבה ב-Vercel:**

   | משתנה | מה זה |
   |---|---|
   | `GOOGLE_CLIENT_ID` | ה-Client ID מהשלב הקודם |
   | `SESSION_SECRET` | מחרוזת אקראית ארוכה משלך — חותמת את עוגיית הסשן |
   | `SUPER_ADMINS` | כתובות הגוגל של מנהלות המערכת, מופרדות בפסיק |

6. נכנסים עם חשבון שמופיע ב-`SUPER_ADMINS`, מגדירים בתי ספר ב"ניהול", וממנים
   לכל בית ספר מנהלת במסך "המורות". מכאן היא זו שמאשרת את המורות שלה.

## התפקידים

| תפקיד | מי ממנה | מה היא יכולה |
|---|---|---|
| מנהלת מערכת | `SUPER_ADMINS` בלבד | הכל: בתי ספר, קטגוריות, מינוי מנהלות, הצמדה, שחזור |
| מנהלת בית ספר | מנהלת המערכת | אישור והסרה של המורות שלה, עריכת כל עיצוב של בית הספר |
| מורה | מנהלת בית הספר | צפייה והורדה, העלאה, ועריכה של מה שהיא עצמה העלתה |
| ממתינה | — | מסך "ממתינה לאישור" בלבד. אפס תוכן |

## מבנה

| קובץ | תפקיד |
|---|---|
| `index.html`, `styles.css`, `app.js` | כל הממשק. בלי framework ובלי build |
| `api/_google.mjs` | אימות ה-ID token של גוגל מול המפתחות הציבוריים שלה |
| `api/auth.mjs` | כניסה, בקשת הרשאה, יציאה |
| `api/users.mjs` | אישור, דחייה, הסרה, הזמנה, מינוי מנהלות |
| `api/items.mjs` | הפריטים, ההרשאות, ורצועת "רלוונטי עכשיו" |
| `api/config.mjs` | בתי ספר וקטגוריות (מנהלת מערכת בלבד) |
| `api/file.mjs` | הורדת קובץ ותמונת תצוגה, מאחורי בדיקת הרשאה |
| `api/upload.mjs` | חתימת העלאה ישירה ל-Vercel Blob |
| `api/_hebrew.mjs` | הלוח העברי: המרת תאריכים, חגים, חלונות רלוונטיות |
| `api/_guard.mjs` | עוגיית הסשן, התפקידים, הגבלת קצב |
| `api/_store.mjs` | מתאם KV מול Upstash |
| `tests/api.test.mjs` | בדיקת קצה-לקצה, כולל חתימת טוקנים אמיתית |
| `docs/spec.md` | האיפיון המלא |

## בדיקות

```bash
node tests/api.test.mjs
```

68 בדיקות. הן מקימות Upstash מדומה בזיכרון **ומפתח RSA שמדמה את גוגל** — כך
נבדק גם מה קורה כשהחתימה לא נכונה, כשהטוקן נועד לאפליקציה אחרת, או כשהוא פג.

## מה עוד לא נבנה

- התראת מייל למנהלת על בקשה חדשה (דורש דומיין ו-Resend). כרגע הבקשות מופיעות
  עם מונה על כפתור "מורות".
- תמונת תצוגה אוטומטית מ-PDF, חיבור Canva Connect, "שמורים אצלי", יומן פעילות בממשק.
